<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → CLI | `--note`, `<unit-id>`, and `unit.md`-supplied intent/audience cross into the recorded audit surface |
| orchestrator → provenance | The HITL gate and the provenance record are the integrity surface AC5 audits depend on |
| core → observability backend | Spans/run_id must not carry secrets into traces/logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.2-01 | Repudiation / Tampering | HITL steering gate (`provenance.steering`) | mitigate | The gate is a domain invariant in `core/orchestrator.py`: draft refuses (nonzero exit, no side effects) without a *prior* recorded `steer` event; steering carries `{author, at}` and provably precedes `generations[].at` (HITL-01/02, AC5) — proven by tests, not prose. |
| T-02.2-02 | Tampering | progress lifecycle reaching `committed` | mitigate | No code path writes `ProgressState.committed`; a test scans transitions and fails if one is added (SKEL-03 / scope border, Pitfall 9). |
| T-02.2-03 | Information Disclosure | secrets leaking into spans / Logfire / provenance | mitigate | Span attributes are restricted to non-sensitive domain fields (`unit_id`, `intent`, `provider`, `run_id`); no env/token values are set as attributes or written to `context_origins`; Logfire runs `send_to_logfire=False` (local only, no egress). |
| T-02.2-04 | Spoofing | recorded author identity | accept | Author is read from local `git config` (D-41); this is trusted-local-operator context, not an authentication boundary — recorded for audit, not enforced cryptographically (consistent with the internal-observability provenance model). |
</threat_model>
