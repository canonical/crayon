<objective>
Build the Wave-0 test scaffolding the implementation plan (03-02) needs to go RED-first, plus the two standalone regression guards that lock the phase's two fragile couplings.

This plan ships three things and touches NO production code:
1. A shared `tests/conftest.py` fake-SDK harness — an extended `_StubClient` whose `create_session(**kwargs)` records `session_kwargs` and returns a scripted `_StubSession` whose `send_and_wait` yields an `assistant.message` event (so the happy path completes), and a factory that can instead raise a scripted exception. This is the harness `test_copilot_session_kwargs.py`, `test_copilot_model_selection.py`, and `test_copilot_error_mapping.py` (all in 03-02) build on.
2. `tests/test_copilot_jsonrpc_import.py` — the D-08 regression guard: imports the private `copilot._jsonrpc.JsonRpcError` and asserts its shape, so a future SDK bump that moves/renames it fails loudly in CI instead of silently dropping the adapter's error catch (RESEARCH Pitfall 2).
3. `tests/test_copilot_toolset_boundary.py` — the V4 security guard: pins `READONLY == {grep, glob, view}` and `DENY` to its exact eight names, so a future edit cannot broaden what `approve_all` (added in 03-02) is allowed to approve.

Purpose: every Wave-1 fix in 03-02 asserts against the fake SDK; that harness must exist first. The two guards are independent regression tests that protect the security and SDK-coupling boundaries the phase widens.
Output: 3 new test files (all with the full GPL-3.0-only SPDX header). No production code changes — the new tests for behaviour-not-yet-implemented live in 03-02 alongside their implementation.
</objective>
