## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> repo | CI executes the gate suite with the default token; the privilege surface |
| third-party GitHub Actions (uses:) -> CI | untrusted action code crosses into the runner |
| developer edit -> seam invariant | the seam gate (CI + pre-commit) is the standing control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering / EoP | third-party GitHub Actions | mitigate | Only first-party actions/checkout + astral-sh/setup-uv, pinned to a tag/SHA; no other uses: entries (RESEARCH Security Domain). |
| T-04-02 | Elevation of Privilege | workflow token scope | mitigate | Top-level least-privilege permissions (contents: read); no secrets added — Phase-1 gates need none. |
| T-04-03 | Tampering (architecture invariant) | seam check bypass | mitigate | The AST seam check runs on EVERY CI build and as a pre-commit hook; the D-10 demo proves it catches a real misplacement (SC4). Residual: dynamic string-constructed imports are out of scope (import-linter is the named Phase-2 successor). |
| T-04-04 | Tampering | gate silencing (ty --exit-zero) | mitigate | The ty step uses plain ty check (no --exit-zero); the documented beta fallback is continue-on-error with a tracked issue, never a checker swap (D-14). |
| T-04-SC | Tampering | dev-tool supply chain in CI | mitigate | uv sync --frozen installs only the pinned uv.lock contents (D-18); reuse via uvx resolves the same version as pre-commit. All tools legitimacy-audited in RESEARCH — no [ASSUMED]/[SUS] checkpoint warranted. |

No high-severity threats in this plan; residual seam-bypass via dynamic string construction is accepted and tracked to the Phase-2 import-linter upgrade.
