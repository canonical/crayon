<objective>
Populate `provenance.yaml`'s `context_origins` and `tools_used` from the Copilot
session's *observed* tool-call events, completing the BL-01 honesty work
(v1.0 stopped fabricating them; v1.1 truthfully fills them). The entire change is
adapter-only: a pure translation helper in `mapping.py`, a two-line observation
in `provider._run_draft`, and the fake-SDK tests that pin it. The domain models,
the orchestrator's verbatim copy, and the seam guards are UNCHANGED in shape.

Purpose: closes the fourth and last gap the 2026-06-20 live run surfaced — the
audit surface was blind (`context_origins: []` / `tools_used: []`) even though the
agent demonstrably read files. PROV-01/02 make the record reflect what actually
happened, kept distinct from the human-pointed `sources`.

Output: `tool_events_to_provenance` in `mapping.py`; the `get_events()` observation
in `provider.py`; `_StubSession.get_events()` in the shared `conftest.py`; and the
new `tests/test_copilot_provenance.py` (pure-helper tests + the criterion-4
fake-SDK end-to-end test).
</objective>

| adapter → core/ | Only plain `list[str]` (`context_origins`, `tools_used`) crosses into `core/` via `DraftResult` — no SDK shape (SEAM-01/03). |
| core/ → provenance.yaml | Derived strings are serialised verbatim into the audit record (unchanged orchestrator path). |

input surface** — it only *observes* events already produced inside the bounded
READONLY session (`grep`/`glob`/`view`; write/exec/network already DENY'd in
Phase 3). ASVS L1; block on `high` only — none expected.
