## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| drafted content → published docs | Provenance/model metadata must not leak into the published `.md` (no public AI disclaimer — PROJECT.md) |
| CI → build output | The docs build produces HTML; build artifacts must not be treated as source by `reuse lint` |
| licensing system-of-record → reuse lint | An inconsistent or wrong SPDX id on content fails `reuse lint` and mis-licenses published prose |

| T-02.4-02 | Tampering | wrong/inconsistent docs license id failing `reuse lint` or mis-licensing content | mitigate | The blocking decision checkpoint resolves CC-BY-SA vs CC-BY-NC-SA; licensing.md §1/§2/§3.5 are reconciled; the license is applied via a verified `LICENSES/*.txt` + `.license` sidecar; `reuse lint` gates it. |
| T-02.4-03 | Tampering | build output (`docs/_build`) entering the tracked tree without headers | mitigate | `docs/_build` is gitignored so generated HTML is never source-scanned by `reuse lint`. |
| T-02.4-04 | Information Disclosure | committing the `.dogen/**` audit surface (`provenance.yaml`) into git history | accept | The audit trail living in git history is the intended AC5 design (D-24, RESEARCH Open Question 3); provenance records only non-sensitive domain metadata (model/version/effort/run_id/context_origins) — no tokens/secrets (enforced by T-02.2-03 in plan 02) — so committing it is a recorded, accepted disclosure of internal observability about the harness, not content. `.planning/` stays excluded (D-30). |
