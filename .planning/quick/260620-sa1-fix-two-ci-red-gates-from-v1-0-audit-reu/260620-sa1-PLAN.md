# Quick Task 260620-sa1: Fix two CI-red gates from the v1.0 milestone audit

**Created:** 2026-06-20
**Source:** `.planning/v1.0-MILESTONE-AUDIT.md` (re-audit, status `tech_debt`)

## Problem

Two CI gates in `.github/workflows/ci.yml` currently exit non-zero on the working
tree, with no `continue-on-error` — so the `gates` job would go red on push:

1. **`uvx reuse lint` → exit 1.** 4 `.planning/` prose files backtick-quote an
   SPDX license-identifier token that the REUSE parser misreads as a real
   license declaration ("Invalid SPDX License Expressions: 4"). Every tracked
   file is correctly annotated; these are parser false-positives (DEF-02-01/02).
2. **`uv run ty check` → exit 1.** `tests/test_orchestrator_hitl.py` passes a
   `_FailingDraftStore` test double (delegating via `__getattr__`) as `store=`,
   with an inline `# type: ignore[arg-type]` that `ty` does not honour. ty sees
   the double as not conforming to the `PlanningStore` protocol.

## Tasks

### Task 1 — Silence the REUSE false-positives (docs housekeeping)
- **Files:**
  - `.planning/phases/01-compliant-scaffold-provider-seam-boundary/01-VERIFICATION.md`
  - `.planning/phases/02-walking-skeleton-planning-schema-provable-hitl-observability/02-01-SUMMARY.md`
  - `.planning/phases/02-walking-skeleton-planning-schema-provable-hitl-observability/02-02-SUMMARY.md`
  - `.planning/phases/02-walking-skeleton-planning-schema-provable-hitl-observability/deferred-items.md`
- **Action:** Wrap each prose SPDX license-identifier mention inline with
  REUSE-Ignore HTML comments (REUSE's documented
  mechanism; already used elsewhere in Phase-1 docs). Keep markdown table `|`
  delimiters and list markers outside the comment so rendering is unchanged. Do
  not alter prose meaning.
- **Verify:** `uvx reuse lint` → "Invalid SPDX License Expressions: 0", exit 0.
- **Done:** repo is REUSE-compliant whole-tree.

### Task 2 — Make the failing-draft test double conform to PlanningStore
- **File:** `tests/test_orchestrator_hitl.py`
- **Action:** Redefine `_FailingDraftStore` as a subclass of
  `FilesystemPlanningStore` (which is stateless — operates on `root` per call)
  overriding only `write_draft` to raise `OSError`. Construct it with no inner
  wrapper. Remove the now-unneeded `# type: ignore[arg-type]` on `store=failing`.
  Behaviour is identical: all other store calls hit the real implementation
  against the same `tmp_path`; `write_draft` still raises "disk full".
- **Verify:** `uv run ty check` → 0 diagnostics; `uv run pytest -q` → 97 passed.
- **Done:** ty gate green, no test regression.
